# Code Review Guidelines

Переиспользуемый чеклист для ревью pull request в этом репозитории — пункты собраны из правил
`CLAUDE.md` (корень, `apps/api`, `apps/web`). Отмечайте пункты `[x]` по ходу ревью; то, что не
прошло, — либо комментарий в PR, либо (если решение осознанно откладывается) пункт в
`.claude/TODO.md`.

## Общее

- [ ] Коммиты в формате Conventional Commits (`<тип>[скоуп]: <описание>`), один коммит — одно
      логическое изменение, без смешения `feat`/`fix` разных концернов.
- [ ] Ветка названа по схеме `<тип>/<описание-на-английском-kebab-case>`.
- [ ] Ломающие изменения помечены `!` после типа/скоупа и футером
      `BREAKING CHANGE: <что и как мигрировать>`.
- [ ] `pnpm typecheck`, `pnpm lint`, `pnpm build` проходят.
- [ ] При изменении `packages/shared` пакет пересобран — зависящие приложения не держат старые
      типы в `dist`.
- [ ] Контракт API меняется в схеме `packages/shared`, а не точечно в DTO.
- [ ] Суммы — канонические строки (`"1234.56"`), арифметика — через `toMinorUnits`/`sumMoney`,
      сервисы прогоняют `amount` через `toMoneyString()` перед отдачей (см.
      `TransactionsService.serialize`).
- [ ] Даты — через `isoDateSchema` (`z.union([...]).transform(...)`), не `z.coerce.date()`.
- [ ] Комментарии объясняют «почему», а не «что»; лишних комментариев нет.
- [ ] Незавершённый хвост (находка требует отдельного решения, пункт плана не проверен)
      зафиксирован в `.claude/TODO.md`, а не остался только в обсуждении PR.

## apps/api

- [ ] Новый эндпоинт либо требует токен по умолчанию, либо явно помечен `@Public()`.
- [ ] `@CurrentUser('sub')` используется вместо ручного разбора `request.user`.
- [ ] Ошибки проходят через `AllExceptionsFilter`/`ZodValidationException`, не через
      самодельный формат ответа.
- [ ] Новый модуль — по структуре
      `modules/<имя>/{<имя>.module.ts, .controller.ts, .service.ts, dto/<имя>.dto.ts}`,
      зарегистрирован в `app.module.ts`.
- [ ] Новые переменные окружения добавлены в `apps/api/src/config/env.schema.ts`.
- [ ] Изменения `schema.prisma` сопровождаются миграцией (`pnpm db:migrate`) и
      `pnpm db:generate`.
- [ ] Новая/изменённая логика сервисов покрыта тестами (`*.spec.ts`, jest).

## apps/web

- [ ] Импорты идут только вниз по слоям FSD; `@/shared/...` — файлом, не барелем;
      `@/<слой>/<слайс>` — только корнем слайса.
- [ ] Нет новых файлов в старых каталогах (`@/lib`, `@/components`, `@/providers`) и
      относительных импортов, пересекающих границу слоя.
- [ ] Защищённые запросы — через `authorizedFetch`, публичные (`/auth/*`) — через `apiFetch`
      напрямую.
- [ ] Access-токен не попадает в React-состояние/контекст (только
      `shared/api/access-token-store.ts`).
- [ ] Новые shadcn-компоненты добавлены через `pnpm dlx shadcn@latest add <имя> --cwd apps/web`;
      импорт `cn` поправлен на `@/shared/lib/cn`; пакет `cn` убран из `apps/web/package.json`,
      если не нужен.
- [ ] Все токены темы, которые печатает новый компонент, объявлены в `@theme`
      (`apps/web/src/app/globals.css`).
- [ ] Тесты (`*.test.ts(x)`, vitest) прогонялись через `pnpm test` /
      `turbo run test --filter=@expense-tracker/web`, не напрямую через
      `pnpm --filter @expense-tracker/web test`.

## После ревью

- [ ] Отложенные решения зафиксированы в `.claude/TODO.md` или в разделе внеплановых находок
      tasks-файла плана (`.claude/plans/<имя>.tasks.md`).
- [ ] Мерж в `master` и удаление ветки — только по явному запросу, не автоматически после
      одобрения ревью.

## Пропускать

- Сгенерированные файлы миграции в prisma/migrations/\*
- Изменения в \*.lock файлах
