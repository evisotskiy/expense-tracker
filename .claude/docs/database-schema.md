# Схема БД и назначение полей

Источник: `packages/database/prisma/schema.prisma` (Postgres, Prisma 7). Сумма (`Decimal(12,2)`)
на выходе из API всегда приводится к канонической строке — см. `.claude/docs/architecture.md` →
«Поток данных».

## `User` (`users`)

Пользователь и его дефолты для новых записей.

| Поле                      | Назначение                                                                                                      |
| ------------------------- | --------------------------------------------------------------------------------------------------------------- |
| `id`                      | `cuid()`                                                                                                        |
| `email`                   | Уникален, логин                                                                                                 |
| `passwordHash`            | Хэш пароля (bcrypt/argon — см. `auth.service.ts`), сырой пароль нигде не хранится                               |
| `name`                    | Необязательно                                                                                                   |
| `baseCurrency`            | Валюта по умолчанию для новых транзакций, ISO 4217 (`RUB`/`USD`/`EUR`), используется как валюта месячной сводки |
| `createdAt` / `updatedAt` | Служебные таймстемпы                                                                                            |

Связи: `categories`, `transactions`, `budgets`, `refreshTokens` — всё каскадно удаляется
при удалении пользователя (`onDelete: Cascade`).

## `RefreshToken` (`refresh_tokens`)

Сессии для ротации refresh-токенов.

| Поле              | Назначение                                                                                   |
| ----------------- | -------------------------------------------------------------------------------------------- |
| `id`              | `cuid()`                                                                                     |
| `userId`          | Владелец                                                                                     |
| `tokenHash`       | Хранится **только хэш** токена, не сам токен — утечка таблицы не даёт выпустить новый access |
| `expiresAt`       | Когда токен перестаёт быть валиден                                                           |
| `revokedAt`       | Проставляется при ротации/логауте; `null` — токен ещё активен                                |
| `userAgent`, `ip` | Контекст сессии (для возможного будущего «активные сессии» в UI)                             |
| `createdAt`       | Когда выдан                                                                                  |

Индекс `[userId, expiresAt]` — быстрый поиск активных сессий пользователя при ротации/логауте.
Каждая ротация создаёт новую строку, старая помечается `revokedAt`, а не удаляется (аудит).

## `Category` (`categories`)

Категория расхода/дохода, принадлежит пользователю.

| Поле                      | Назначение                                                                                                         |
| ------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| `id`                      | `cuid()`                                                                                                           |
| `userId`                  | Владелец                                                                                                           |
| `name`                    | Название, уникально в рамках пользователя (`@@unique([userId, name])`), не глобально                               |
| `icon`                    | Имя иконки из `lucide-react`, например `"utensils"`                                                                |
| `color`                   | HEX-цвет для графиков, например `"#22c55e"`                                                                        |
| `isArchived`              | Мягкое удаление: архивную категорию нельзя выбрать в новой транзакции, но она сохраняет историю и подпись в сводке |
| `createdAt` / `updatedAt` | Служебные таймстемпы                                                                                               |

Индекс `[userId, isArchived]` — фильтрация активных категорий в списках. Удаление категории —
всегда архивирование (`isArchived = true`), не DELETE: FK на `Transaction.categoryId` и
`Budget.categoryId` — `Restrict`/`Cascade` соответственно (см. ниже), а бизнес-правило не
позволяет терять историю.

## `Transaction` (`transactions`)

Одна таблица на доходы и расходы — они отличаются только знаком в отчётах (`type`), а запросы
(лента, фильтры, итоги за месяц) у них общие.

| Поле                      | Назначение                                                                                                                |
| ------------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| `id`                      | `cuid()`                                                                                                                  |
| `userId`                  | Владелец                                                                                                                  |
| `categoryId`              | Обязателен — без категории транзакция не попадает ни в одну строку отчёта и молча искажает итоги                          |
| `amount`                  | `Decimal(12,2)`, **всегда положительный** — знак несёт `type`, а не сама сумма                                            |
| `type`                    | `INCOME` \| `EXPENSE`                                                                                                     |
| `currency`                | ISO 4217; дублируется из `User.baseCurrency` на момент создания, чтобы смена валюты пользователем не переписывала историю |
| `description`             | До 500 символов, необязательно                                                                                            |
| `date`                    | Когда деньги реально пришли/ушли — не момент создания записи                                                              |
| `createdAt` / `updatedAt` | Служебные таймстемпы                                                                                                      |

FK `categoryId → Category`: `onDelete: Restrict` — архивация категории (а не DELETE) обходит
это ограничение; `Restrict` защищает от случайного физического удаления категории, на которой
висит история.

Индексы:

- `[userId, date desc]` — главный запрос приложения: «транзакции пользователя за период,
  свежие сверху» (лента и сводка).
- `[categoryId]` — нужен проверке `Restrict`: без него Postgres делает seq scan по
  `transactions` при каждой попытке удалить категорию.

## `Budget` (`budgets`)

Лимит трат — общий или по конкретной категории, на период.

| Поле                      | Назначение                                                                                              |
| ------------------------- | ------------------------------------------------------------------------------------------------------- |
| `id`                      | `cuid()`                                                                                                |
| `userId`                  | Владелец                                                                                                |
| `categoryId`              | `null` — общий лимит на все расходы; иначе лимит по конкретной категории                                |
| `amount`                  | `Decimal(12,2)`, лимит                                                                                  |
| `currency`                | ISO 4217                                                                                                |
| `period`                  | `WEEKLY` \| `MONTHLY` \| `YEARLY`, по умолчанию `MONTHLY`                                               |
| `startsAt`                | Точка отсчёта периодов — сами периоды вычисляются на лету (`budgetPeriodRange` в `shared`), не хранятся |
| `endsAt`                  | Необязательная дата окончания действия бюджета                                                          |
| `createdAt` / `updatedAt` | Служебные таймстемпы                                                                                    |

FK `categoryId → Category`: `onDelete: Cascade` (в отличие от `Transaction` — здесь нет
смысла сохранять бюджет без категории, на которую он рассчитан).

Уникальность `[userId, categoryId, period]` — один бюджет на связку «пользователь + категория +
период». В Postgres `NULL` не конфликтует сам с собой, поэтому общих бюджетов (`categoryId = null`)
с одинаковым периодом может быть несколько — это должен проверять сервис отдельно (на момент
написания `BudgetsService.create/update/remove` — заглушки, см. `.claude/docs/api.md`).

Индекс `[userId]` — выборка всех бюджетов пользователя.

## Перечисления

| Enum              | Значения                      | Где используется   |
| ----------------- | ----------------------------- | ------------------ |
| `TransactionType` | `INCOME`, `EXPENSE`           | `Transaction.type` |
| `BudgetPeriod`    | `WEEKLY`, `MONTHLY`, `YEARLY` | `Budget.period`    |

Оба объявлены в shared независимо от Prisma-enum (`packages/shared/src/schemas/*.ts`): пакет
`shared` не зависит от `@expense-tracker/database`, и фронтенд не должен тянуть Prisma-клиент
ради пары строк.
