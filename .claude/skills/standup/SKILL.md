# Стендап-отчёт

Skill только читает историю и ничего не меняет: не стейджить, не коммитить, не переключать ветки.

## Порядок

1. Определить автора: `git config user.email` — отчёт строится только по его коммитам.
2. Определить период — «вчера» от 00:00 до 24:00 локального времени. Если сегодня понедельник,
   брать последний рабочий день (пятницу), а не воскресенье, и сказать об этом в отчёте.
3. Собрать коммиты по всем веткам, а не только по текущей:

   ```bash
   git log --all --author="<email>" --since="<начало>" --until="<конец>" \
     --no-merges --format='%h %ad %s' --date=format:%H:%M
   ```

4. Для каждого коммита посмотреть, что реально изменилось: `git show --stat <hash>`, а для
   неочевидных — `git show <hash>`. Одного заголовка коммита недостаточно: отчёт должен
   объяснять суть, а не пересказывать `git log`.
5. `git status` — отметить незакоммиченную работу отдельно как «в процессе», не выдавая её за
   сделанное вчера.

## Формат отчёта

Вывод — прямо в ответе, на русском, без записи в файлы.

- Группировать по смыслу задачи (фича, багфикс, документация, рефакторинг), а не по коммитам
  подряд; несколько коммитов одной задачи объединять.
- Для каждой группы: что сделано и зачем (если причина видна из тела коммита или диффа), какие
  модули/пакеты затронуты (`apps/api`, `apps/web`, `packages/shared`), заметные детали —
  новые эндпоинты, миграции, ломающие изменения.
- В конце — список затронутых коммитов (`хеш — заголовок`) для проверки.
- Раздел «В процессе» — только если есть незакоммиченные изменения.
- Если за период коммитов нет — прямо сказать об этом и показать «В процессе», не выдумывать
  работу.

## Ограничения

- Не придумывать то, чего нет в истории: никаких оценок времени, статусов задач и планов на
  сегодня, если пользователь не просил.
- Не включать чужие коммиты, даже если они в тех же ветках.
- Не трогать удалённый репозиторий: без `git fetch`/`git pull`.
